# Contributing to Cortexcn

Thanks for helping. Cortexcn is a registry of React and Tailwind CSS components, page blocks, and charts, installed with the shadcn CLI. This guide covers how to run it locally and what a good pull request looks like.

## Before you start

- For a bug, open an issue with the item name, what you expected, what happened, and the steps to see it.
- For a new component or block, open an issue first so we can agree on the API before you build it.
- Small fixes (typos, broken links, docs) can go straight to a pull request.

## Set up

You need Node.js 18 or later and [Bun](https://bun.sh) 1.4.0, the version pinned in `package.json`.

```bash
bun install
bun run dev
```

Run scripts with `bun run <script>`. `bun build` and `bun test` start Bun's own bundler and test runner instead of the repo scripts.

The services site runs at http://localhost:4410, the component library home at http://localhost:4420, and the components docs at http://localhost:4430. The ports are set in `apps/web/dev-ports.json`.

## Where things live

| Path | What it is |
| --- | --- |
| `packages/ui/src/components` | Component source, published to the registry |
| `packages/ui/src/charts` | Chart components and their parts |
| `packages/ui/registry.json` | The registry index: every item, its files, and dependencies |
| `apps/web/blocks` | Page blocks and their previews |
| `apps/web/content/docs` | Docs pages (MDX) |
| `apps/web/public/r` | Published registry JSON, generated by `bun run registry:build` |
| `templates/portfolio` | The free Portfolio template |

`AGENTS.md` has the step-by-step for adding a component, block, or chart.

## Make a change

1. Create a branch from `main`.
2. Make the change, with a docs page or example when you add or change an item.
3. If you changed anything in the registry, run `bun run registry:build` and commit only the files your change touched.
4. Run the checks:

   ```bash
   bun run lint
   bun run check-types
   bun run build
   ```

5. Open a pull request that says what changed and why, with a screenshot for anything visual.

## Style

- TypeScript with strict types. Biome formats and lints (`bun run lint:fix`).
- Colors come from theme tokens and corners from the radius scale; see `packages/ui/src/agents/DESIGN.md`.
- Every interactive element works with the keyboard, shows a focus ring, and respects reduced motion.
- Keep components dependency-light. Explain any new dependency in the pull request.
